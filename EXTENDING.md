# Extending pixelfit

A map of the seams, for anyone building the next lane. Everything here
is stdlib Python; the repo has no package dependencies by design and
new lanes should keep it that way.

## Module map

- `pngio` - PNG decode/encode (8-bit, non-interlaced, gray/RGB/RGBA)
- `imageops` - Image container, area resample, grayscale, blur, dilate
- `metrics` - the three comparators: YIQ color diff, SSIM grid,
  Sobel edge IoU (all operate on flat scalar maps)
- `regions` - mismatch-mask clustering + region labeling
- `core` - `compare_images()` orchestrates the pipeline; owns
  `PROFILES` weights and the report dict shape
- `phash` - 64-bit dHash for library candidate pruning
- `library` - screen-state dictionary + `match()` ranking
- `cli` - subcommands (`compare`, `match`); bare `design impl` is
  kept backward-compatible

## The contract between lanes and the core

A capture lane (web, Android, anything future) only has to produce:

1. an `Image` (screenshot) - feeds `core.compare_images` directly
2. optionally, ignore rects in design-pixel coordinates
3. optionally, per-element boxes - regions in the report already carry
   `x0/y0/x1/y1` boxes; element attribution belongs in a new
   `element` key on each region dict, populated by the lane

Nothing in `core` or `metrics` needs to change for a new capture
source. The report dict is JSON-safe end to end; extend it additively.

## What exists vs. what each roadmap rung must build

- Overlay web viewer: new `www/` single-file client + stdlib
  `http.server` route in `cli`; consumes `report.json` as-is
- Web capture lane: NOT scaffolded. Requires a from-scratch CDP client
  in-repo (WebSocket handshake per RFC 6455, frame codec, then
  `Page.navigate` + `Page.captureScreenshot` + a DOM snapshot for
  element boxes). No existing module covers this; that protocol client
  is the substance of the rung
- Android capture lane: shell out to `adb` (`exec-out screencap`,
  `uiautomator dump`); parse the XML with `xml.etree`; boxes feed the
  `element` key above
- Design-JSON lane: JSON parser producing declared geometry/values;
  compare against the same report
- Automation harness (Maestro or similar): orchestrate an external
  tool, map screenshots to library keys, aggregate per-step verdicts;
  `library.match` is the engine

## Runtime tools are environment checks, not dependencies

Chromium, `adb`, and `maestro` are expected to exist on the machine
when the corresponding lane runs; the repo never installs or vendors
them. A lane should fail with a clear "tool not found" message naming
the binary, and tests for a lane must skip cleanly when the tool is
absent so offline `unittest discover` stays green everywhere.

## Conventions

- New features come with deterministic fixtures generated by a script
  under `fixtures/`, carrying ground truth the tests gate on
- Measured thresholds only: run the metric, then set the gate slightly
  under the measured number, and document the ceiling in the README
- Region boxes use design-pixel coordinates, `x1/y1` exclusive
